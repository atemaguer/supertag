# Rust port capability ledger

Internal contributor record for the Rust rewrite. It is not user documentation and makes no
product claim. The ledger defines when the rewrite is done: every row is either covered, a
recorded deliberate change, or dropped with approval.

**Location.** The assignment asked for `contributing/rust-port-capability-ledger.md`. In this
repository `contributing/` is gitignored (`.gitignore` line 35) and `AGENTS.md` keeps internal
design notes there, so a file there could not be committed or reviewed. The assignment's fallback
is `rust/docs/`, which is tracked. Nothing under `docs/` links here.

**Baseline.** The TypeScript product at the rewrite's merge base with upstream, `a369dc4`, which
includes the `0b6a8ff` baseline named by the approved design.

## How to read this ledger

Capabilities were derived by sweeping `tests/` (306 test files), `tests/e2e/`, `tests/runtime/`,
`packages/**/*.test.ts`, `apps/cli/*.test.ts` and `helpText()` in `apps/cli/src/index.ts`,
`apps/tui/*_test.go`, `sdks/python/tests/`, and every page under `docs/`. The progress log was
used only to find where Rust evidence lives.

Rust evidence was identified from the test function names in `rust/crates/*/tests/*.rs` and
`#[cfg(test)]` modules, and from the store, RPC, and CLI operations each test invokes. Tests marked
**(read)** were read in full while writing this ledger. The rest were checked by name and by the
operations they call, which shows what they exercise but not every assertion.

| Status | Meaning |
| --- | --- |
| **Both DBs** | A Rust test exercises the capability on SQLite and on PostgreSQL |
| **SQLite only** | Rust coverage exists, but no PostgreSQL run of that behavior exists |
| **Partial** | Some of the TypeScript behavior has Rust coverage; the gap column says what is missing |
| **Open** | No Rust implementation or no Rust test was found |
| **Changed** | Deliberately different in Rust under the approved design; the reason is given |
| **Dropped** | Removed with the user's approval; the approval is cited |

Approved scope decisions cited below are from the approved design
(`rust-port-design-and-plan.md`, section 1) and the November 12 handoff: no compatibility with
old runtime, wire, API, or Worker interfaces; fresh Rust state with old data archived and no
importer; separate Gateway; Go TUI and Tauri desktop retained; TypeScript and Python keep client
SDKs and harness adapters but no longer implement full Worker runtimes.
